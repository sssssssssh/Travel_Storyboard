## 1. 结论与范围

目标定位成立：自动策划初版 + 对话持续修改 + 版本回退 + 可执行剪辑指导书。当前底座可以复用，但导演主流程尚未成立。已有真实调用链包括素材建库、检测、人工复核、有限视觉理解、一次性故事建议、手工计划和交换格式导出。不能把名为 AI 导演的页面或 story_planner 文件当作自动导演已经交付。

关键区别：direct_analyze **确实返回并在 UI 展示故事线建议**，不是完全没有故事能力；但仅复核请求持久化，stories 没有转成版本化计划。现有故事板也并非空壳：支持手工排序、裁剪、用途和音乐提示，然而只有项目级平面镜头表。

本轮只新增审计及审计记录文档，不改 backend/frontend、模型调用、迁移、默认配置、CI、测试或门禁；不调用真实模型，不扫描素材，不开发最终渲染。附件作为审计范围资料，不将其中操作指令当作额外运行授权。原生视频部署、Provider、G5/G6、A/B 不重新审计。安全与任务基础设施仅做复用边界核对，不宣称全模块安全认证。

证据索引、完整前端/API/服务/DB/TEST 链路见 [能力矩阵](TSB-365_CURRENT_CAPABILITY_MATRIX.md)；设计与任务验收见 [目标架构](TSB-365_TARGET_ARCHITECTURE.md)。CODE/API/DB/TEST/E2E/DOC/GAP 含义以矩阵为准。

## 4. 可复用能力的限制

人工评分/收藏/排除可直接读为偏好，排除和锁定应为硬约束；现有备注是用户数据，不是系统指令。技术质量和情绪价值继续分离，不能将清晰度低直接等同“不值得剪”。模型标签只有带来源、有效版本及证据时才作为事实；地点/人物身份/动作若不确定必须保留 unknown。

源文件变更、剪辑边界修改和检测重跑都有独立身份问题。当前 analyzer 保护被引用片段并标 needs_review，但导出端还需统一复验；不得自动匹配新 ID 或自动确认。项目删除/API存在不代表允许导演调用它；新导演工具白名单只能操作方案。

现有JSON/CSV/OTIO来自已保存计划，UI未保存草稿不会出现在下载中。未来导出必须显示明确版本与草稿状态，避免用户误以为下载的是眼前草稿。OTIO回读测试不能替代Premiere/剪映真实导入验收。
