## P1-01 人工评价真正进入策划

**问题**：`build_planning_input()` 从未读取评价表。判错的句子照旧进入方案。

**修复**：在构建 PlanningInput 时按**断言级**过滤。

| 人工评价 | 策划处理 |
|---|---|
| 全部正确 | 正常使用对应证据 |
| 部分错误 | **只隔离判错的断言**，正确断言保留 |
| 无法判断 | 不作为错误依据 |
| 未评价 | 沿用现有证据策略 |
| 模型结果过期 | 旧评价不影响新结果 |

按任务书 §2 的要求：**描述错误不等于镜头没有价值**。因此：
- 不排除镜头、不缩窗口、不删除任何东西；
- 每条证据与镜头带 `human_review_*` 限制说明（不静默）；
- review 摘要折入 `source_input_digest`，过滤后的方案与未过滤的方案
  **不可能同指纹**。

**验收**：`tests/test_tsb371r1_planning_feedback.py`（14 项）

## P1-02 三渠道逐句评价

**问题**：原实现只为静帧生成评价项，多帧与原生视频没有映射。

**修复**：按**真实生产结构**提取（不编造字段）：

| 渠道 | 断言来源 |
|---|---|
| 静帧 | `analysis_json` 的 scene_tags / subjects / visible_actions / lighting / composition / mood |
| 多帧 | `analysis_json` 的 motion_type / stability_risk / action_summary + `evidence_json.frames[].time_sec` |
| 原生视频 | `analysis_json.summary` + `events_json[].description`，事件窗口单独给出 |

- 模型没输出的字段**不产生断言**；
- 不同渠道的 claim key 不共享；
- 时间类断言可定位到源绝对秒。

**验收**：`tests/test_tsb371r1_channels.py`（9 项）

## P1-04 claim 完整性与报告增强

**问题**：服务端不校验 claim_key 是否属于冻结的原始断言。

**修复**：
- 以 `EvaluationItem.readings_json`（会话冻结快照）为准校验；
- 未知 key → `422 EVAL_CLAIM_UNKNOWN`；
- 跨项目 key → 404；
- 重复 key 去重（后者覆盖前者）；
- 校验失败**不半写入**；
- 报告新增 `claims` 表：原文、判断、渠道、result_id、是否计入；
- CSV 改为每条断言一行；Markdown 增「判错的句子」。

**一个被暴露的旧缺陷**：9 处旧测试使用了**不存在的 claim key**
（如 fixture 只有 `subjects:0` 却测试 `subjects:1`）——它们以前能过，
是因为**根本没有校验**。断言强度未降低，只把 key 改为真实存在者。

**验收**：`tests/test_tsb371r1_integrity.py`（12 项）

## P1-03 A/B 真实性与差异判断

### 缺陷一：内容指纹含元数据

原来的 `_fingerprint()` 对整个 draft 做哈希，`planning_mode` 在内，
**两套剪辑内容完全相同的方案被判为不同**，假 A/B 得以通过。

**修复**：`content_fingerprint()` 只含
镜头顺序 / segment_id / 源区间 / 叙事角色 / section / 时长。
排除 planning_mode、model/provider/call_id、warnings、limitations、
selection_reason 散文。

### 缺陷二：客户端可伪造回执

原检查只问「四个字段非空」。

**修复**：新增 `model_call_records` 表，**只由可信策划链写入**。
`has_model_receipt()` 必须找到同项目、`purpose=director_plan`、
`succeeded=True` 的服务端记录；无 session 一律 False。

- 客户端填写的回执 = 无证据；
- 失败的调用不算证据；
- 跨项目记录不算证据。

**验收**：`tests/test_tsb371r1_ab_trust.py`（15 项）

## P1-05 已提交会话恢复

**问题**：`blind_view()` 无条件返回 `revealed: False`。提交后刷新回到盲评，
**揭示结果丢失**（映射其实还在数据库里）。

**修复**：`current_view()` 由服务端存储状态决定。
`wants_reveal` 参数只记录不覆盖真相——客户端既不能提前揭示，
也不能隐藏已揭示结果。

**验收**：`tests/test_tsb371r1_ab_resume.py`（10 项）

## P1-06 媒体过期校验

**问题**：`clip_status()` 能发现源变化，但**媒体路由从不询问**。
源文件被替换后，旧片段仍按当前素材播放——评价者拿模型描述去对照
一段已经不属于它的画面。

**修复**：抽出 `staleness()` 由状态接口与媒体路径共用；
过期抛 `EVAL_CLIP_STALE`(409)，消息带重新生成提示。

**保留**：Range/HEAD、时间映射、静音派生、源只读。
**仍拦截**：跨项目、未知 clip、路径穿越、缓存外逃逸。

**验收**：`tests/test_tsb371r1_clip_staleness.py`（12 项）

## P2-01 消除 N+1

**实测**：100 镜头 **300 次查询**；1000 镜头 **3000 次**；
候选路由单请求 **120 次**评价查询。

**修复**：`verdicts_for_project()` 一次加载三张表在内存分组，
与单条 `review_verdict()` 共用 `_summarise_verdicts()`，两者不可能不一致。

**验收**：`tests/test_tsb371r1_perf.py`（6 项），断言查询数不随镜头数增长。

## P2-02 并发与 409

**结论**：现有实现**已正确**。这轮是验证而非修复。

- 版本冲突 → 409，不静默合并；
- 被拒绝的写入不改变既有数据；
- 快速连点不丢判断；
- 乱序到达不覆盖较新判断；
- 6 线程并发保存后状态一致。

**验收**：`tests/test_tsb371r1_concurrency.py`（7 项）

## P2-03 G3/G4 状态

**问题**：状态是**硬编码字符串**，写完后永远不变。

**修复**：从 `model_call_records` 计算：

| 状态 | 条件 |
|---|---|
| `PASS` | 存在成功的对应 purpose 调用 |
| `BLOCKED` | 有尝试但失败 |
| `NOT_RUN` | 未尝试——**绝不默认 PASS** |

A/B 页面存在 ≠ A/B 发生过。

**验收**：`tests/test_tsb371r1_gates.py`（11 项）
