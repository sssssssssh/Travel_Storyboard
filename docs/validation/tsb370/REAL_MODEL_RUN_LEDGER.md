## 5. 执行过程中发现的缺陷（均为我引入或暴露的真实问题）

### 缺陷 1：前 2 次探测未留存响应

`max_tokens` 设为 8/16，推理型模型把预算耗在 reasoning 上，
`content` 为 null。**浪费了 2 次 probe 额度**而未得到能力结论。

修复：后续调用统一用 `vision_max_tokens=4000`。

### 缺陷 2：账本 channel 被环境变量固定

服务进程首次启动时 `TRAVELSB_MODEL_LEDGER_CHANNEL=static`，
导致多帧请求被记入 `static` 桶（cap 12 已满而拒绝）。
**这正是账本要防止的错记。**

修复：改为 `ContextVar`，由各任务入口（`vision_analyze_task` /
`motion_review_task` / `video_analyze_task`）各自声明渠道。

### 缺陷 3：隔离库复制未带帧文件

首次 3 次 job 全部 `INSUFFICIENT_FRAMES`。根因链：
1. `frames.image_path` 内嵌**原项目 ID**；
2. 隔离目录下不存在该路径；
3. 尝试 junction 链接 → `resolve_in_project()` 的 `_contained()` 用 `resolve()`
   穿透链接，判定为"逃逸出项目缓存目录"而拒绝（**这是正确的安全行为，不应削弱**）；
4. 最终改为**复制帧文件**到隔离目录（帧是派生产物，复制不触碰原片）。

### 缺陷 4：相对导入深度错误

`from ..providers.openai_compatible` 在 `app.services.vision.*` 中应为
`from .providers...`。导致多帧任务 `ModuleNotFoundError`，一次真实请求被浪费
（该次记为失败，未产出结果）。
