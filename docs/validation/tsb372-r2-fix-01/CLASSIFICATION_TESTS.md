# 原生视频能力分类回归

| 视频响应 | 纯文字健康对照 | 判定及诊断 |
| --- | --- | --- |
| 415 | 2xx | `unsupported`，当前协议的视频媒体类型被拒绝 |
| 400，明确 `video=0` 或 vLLM 原始零额度消息 | 2xx | `unsupported`，准确指出 `--limit-mm-per-prompt video=1` 的服务端配置阻塞 |
| 400，明确拒绝 `video` 或 `video_url` content part／视频输入 | 2xx | `unsupported`，保留当前接口不识别视频输入的诊断 |
| 普通 400、422、非零视频额度、非视频 content part 的错误 | 2xx | `unverified`，优先检查格式及参数 |
| 413 | 任意 | `unverified`，缩小请求后重试 |
| 401、403、404、429、500、502、503、网络异常及超时 | 任意 | `unverified`，保留 HTTP 状态或运输层错误码 |
| 视频负面响应 | 非 2xx 或无健康结果 | `unverified`，诊断保留对照状态或提示先完成文字检查 |

默认多轮命令的报告沿用失败视频轮次所见的 HTTP 状态、原始错误码和经过脱敏的响应摘要。避免把没有 HTTP 响应的超时汇总为 200。既有单轮和多轮时序门禁继续生效。

基线直接分类红测涵盖模糊 400、422、413、对照错误及未执行对照。生产 CLI 多轮接线用测试替身复现历史 `video=0`、普通 400 和超时三类结果，共 3 项红测。用仓库中的 R2 历史 400 响应与健康 200 对照离线复算，结果确认原部署的零视频额度，无新的远端请求。
