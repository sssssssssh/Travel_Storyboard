## 四、服务端需要改什么

vLLM 的启动参数里需要显式放行视频数量。当前等价于 `--limit-mm-per-prompt video=0`。

```
--limit-mm-per-prompt video=1
```

**注意**：该参数是**逗号分隔的复合值**，设了 video 就会**覆盖** image 的默认值，
所以通常要同时写全：

```
--limit-mm-per-prompt image=4,video=1
```

否则可能出现"视频通了、图像反而被限成 0"的回归。

并且必须确认**模型本身在该 vLLM 版本下接受视频**：

- 视频支持要求 vLLM ≥ 0.6.x 且模型有对应 processor；
- 若该版本根本不认 `video` 这个 key（早期只支持 `image`），则会报参数非法或忽略，
  需要升级 vLLM 或换用支持视频的 serving 配置。

**推荐验证顺序**（每步都便宜、都是 1 次请求）：

1. 部署重启后，先用上面第 1 条（单次合成视频）确认 400 → 200；
2. 通了再跑完整阶段 B（6 次请求）；
3. 仍 400 且错误文本仍是 `At most 0 video(s)` → 参数没生效（检查是否被部署模板覆盖 /
   是否改在了另一个部署上）；
4. 错误文本**变了**（比如 `Unsupported` / `processor` / `multimodal` 相关）→ 说明上限已开，
   但模型/serving 不支持视频，那是另一类问题，需记录新的证据。
