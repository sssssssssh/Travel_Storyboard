## 实机操作

1. 选取 8～10 段真实旅行视频：至少一段约 10 分钟、一段几十秒、横屏与竖屏、有音轨与静音；有 HEVC/4K 或 VFR 时一并纳入。先选小样本，不跑全部 200GB。
2. 对选取的原片记 SHA-256/文件大小/mtime；将记录写到独立验收目录，不能写入原片目录。记录前后哈希的读盘量另计。
3. Windows 从仓库执行 `scripts\start.bat` 或 `scripts\start.ps1`。使用默认快速校验建立项目、扫描、检测；确认 10 段都出现，失败项显示原因。保存 Job ID 与失败列表。
4. 为至少一个镜头收藏、填用途和备注、保存人工裁剪并建剪辑计划；生成默认包和收藏包，核对 JSON/帧/联系表一致，ZIP 不含旧 stale 镜头、源路径或 EXIF。
5. 导入有效 0.6 秒请求及一个越界请求，确认部分成功和错误定位；生成预览并播放、拖动，核对原片入出点。源静音应正常生成可播放视频。
6. 请求入库后收紧裁剪再导出，确认不编码越界；编码中改裁剪/取消/替换**测试副本**，确认旧正式预览仍在，新临时文件不发布。不得为模拟替换而改动用户原片。
7. 在 UI 选择当前有效镜头，显式新建替代请求；确认旧请求 superseded，新旧 ID 关联完整，旧收藏/备注/用途与原计划引用保留。暂缓与放弃均不清除人工状态，旧计划必须人工修正后才能生成完整新粗剪。
8. 默认与自定义工作区都做一次预览读取，另一项目不能读取该预览。重跑扫描/检测记录增量跳过数；失败项修复后用明确重试操作处理。
9. 按需要另建小任务选择完整校验/严格复核，记录 hashing/processing/hash_recheck、bytes_read/total_bytes、hash_restarts/strict_extra_bytes，不用耗时外推 200GB。完整扫描和检测各读一遍，200GB 分别执行可能额外读取约 400GB；严格复核和重试会更多。
10. 再次记原片 SHA-256/大小/mtime，逐项比对不变；保存可脱敏的截图、Job JSON 与播放器定位记录。记录不通过项及恢复方式。
