## 一、实机操作（沿用 v2.0.3 的 10 步）

1. 选取 8～10 段真实旅行视频：至少一段约 10 分钟、一段几十秒、横屏与竖屏、
   有音轨与静音；有 HEVC/4K 或 VFR 时一并纳入。先选小样本，不跑全部 200GB。
2. 对选取的原片记 SHA-256/文件大小/mtime；记录写到独立验收目录，
   不能写入原片目录。
3. Windows 从仓库执行 `scripts\start.bat` 或 `scripts\start.ps1`。
   使用默认快速校验建立项目、扫描、检测；确认 10 段都出现，失败项显示原因。
   保存 Job ID 与失败列表。
4. 为至少一个镜头收藏、填用途和备注、保存人工裁剪并建剪辑计划；
   生成默认包和收藏包，核对 JSON/帧/联系表一致，ZIP 不含旧 stale 镜头、
   源路径或 EXIF。
5. 导入有效 0.6 秒请求及一个越界请求，确认部分成功和错误定位；
   生成预览并播放、拖动，核对原片入出点。源静音应正常生成可播放视频。
6. 请求入库后收紧裁剪再导出，确认不编码越界；编码中改裁剪/取消/替换
   **测试副本**，确认旧正式预览仍在，新临时文件不发布。
   **不得为模拟替换而改动用户原片。**
7. 在 UI 选择当前有效镜头，显式新建替代请求；确认旧请求 superseded，
   新旧 ID 关联完整，旧收藏/备注/用途与原计划引用保留。
8. 默认与自定义工作区都做一次预览读取，另一项目不能读取该预览。
   重跑扫描/检测记录增量跳过数；失败项修复后用明确重试操作处理。
9. 按需要另建小任务选择完整校验/严格复核，记录 hashing/processing/hash_recheck、
   bytes_read/total_bytes、hash_restarts/strict_extra_bytes，不用耗时外推 200GB。
10. 再次记原片 SHA-256/大小/mtime，逐项比对不变；
    保存可脱敏的截图、Job JSON 与播放器定位记录。

## 二、v2.0.4 新增验收项

### RT-20：Windows 深路径全链路（TSB-241）

> 前提：**不启用** `LongPathsEnabled`（即 Windows 默认状态）。
> 验证方法：`Get-ItemProperty 'HKLM:\SYSTEM\CurrentControlSet\Control\FileSystem' -Name LongPathsEnabled`

1. 把项目输出工作区设到一个 **≥270 字符**的目录，另一次用 **≥320 字符**。
   构造方式（逐层建目录，注意用扩展长度形式才能建出超限目录）：
   ```powershell
   $p = "D:\TSB"
   while ($p.Length -lt 280) { $p = Join-Path $p ("d" * 40) }
   New-Item -ItemType Directory -Path "\\?\$p" -Force | Out-Null
   ```
2. 在该工作区下建项目，导入真实素材。
3. 依次执行并确认**每一步都产出可读取的文件**：
   扫描 → 检测 → 抽帧 → 分析包 → 二轮代理 → 粗剪 → HTTP 预览播放。
4. **断言原片字节未变**（对照步骤 2 的 SHA-256/大小/mtime）。
5. 故意制造失败（例如把工作区设到无权限位置），确认：
   - 报错**能定位到阶段**，并给出 `PATH_TOO_LONG` / `OUTPUT_NOT_CREATED` /
     `MEDIA_UNREADABLE` 之一；
   - **不出现**「FFmpeg 返回 0、Python 后续找不到文件」这类含糊表现。
6. 浅路径与 Ubuntu 路径各跑一次，确认无回归。

### RT-21：任务互斥（TSB-242）

1. 启动一次检测任务，在其运行期间：
   - 用 UI 再点一次检测 / 生成预览 / 粗剪；
   - 用 `curl` 直接打 `/api/projects/{id}/review-requests/proxies`。
2. 全部应返回 **409**，且响应含冲突任务的类型与 ID。
3. 检查该项目的 Job 列表：**不应出现排队的重复任务行**。

### RT-22：代理时长验收（TSB-243）

1. 对一个已知时长的区间生成代理（含约 0.6 秒的短请求）。
2. 用 `ffprobe` 实测代理时长，与请求区间比对，偏差应在
   `max(0.25s, 10%)` 之内。
3. 制造一次异常（例如在编码中途把**测试副本**截断），确认：
   - 该请求**不会**被标成 `proxied`；
   - 任务为 `partial_failed` 且失败项带 `[DURATION_MISMATCH]`；
   - **既有代理引用未被覆盖**。

## 四、门禁说明

按 v2.0.4 任务书要求，以下任一情形即视为**未达发布门禁**：

- 任一 P1 任务缺少可复现回归测试，或仍出现「输出成功但文件不存在」；
- 重复任务创建绕过互斥，产生多个同项目活跃互斥 Job；
- 代理实际时长明显异常仍标记 `proxied`，或失败时覆盖历史代理；
- Windows 深路径导致未提示的抽帧/粗剪失败；
- 原片前后 SHA-256 变化，或历史 SQLite / EditPlan / ReviewRequest /
  收藏备注被删除；
- **未完成 RT-18/19 却声称已满足真实素材发布门禁**。

前五项在本轮已由自动化守住（见 [`../../REGRESSION.md`](../../REGRESSION.md)）。
第六项取决于本文件的实测记录 —— **在表格填写完成前，v2.0.4 不应宣称
已满足真实素材发布门禁**。
