## 逐项：问题 → 修复 → 验收

### 1. 测试写死 `"ffmpeg"`，本机报 17 个 ERROR（WinError 2）

- **问题**：`tests/test_video_provider_wiring.py` 的 `_make_source()` 用裸 `"ffmpeg"`
  启动子进程；本机 FFmpeg 不在 PATH（`locate_ffmpeg()` 只服务产品代码路径），
  `require_ffmpeg()` 的返回值被丢弃。连累 import 同一 helper 的
  `tests/test_video_e2e_formal_api.py`，两文件共 **17 个 setup ERROR**。
  CI 装了 PATH 里的 FFmpeg，所以全绿——正是「接线在、值没用」的 TSB-253 类缺陷。
- **修复**：命令第 0 个元素改用 `require_ffmpeg()` 返回值。
- **验收**：FFmpeg 仍不在 PATH 的同一台机器上，两文件 17/17 通过。
  逆向验证：改动前这两文件全红（轮 1）。

### 2. 悬空符号链用例在无特权 Windows 上直接 OSError（WinError 1314）

- **问题**：`test_staging_leaf_substitution.py` V17 / V17b 与
  `test_video_fallback_execution.py` V37 直接 `os.symlink(...)`，
  无 `SeCreateSymbolicLinkPrivilege` 的 Windows 进程直接抛 OSError。
- **修复**：按仓库既有约定改为 `pytest.skip("link creation is a platform fact")`
  （该原因**已在** `conftest._EXPECTED_SKIP_REASONS` 白名单，未放宽守卫；
  CI 的 Windows/macOS/Linux 均可建链，覆盖不受影响）。
- **验收**：轮 3 中这 3 个用例为 skipped 而非 failed；白名单 skip 守卫未触发告警。

### 3. 有界注册表用例依赖全局 `_OWNERS/_CLEANED`（58 ≠ 59）

- **问题**：`tests/test_vision_staging_ownership.py` 的
  `test_success_registry_is_bounded...` 假设全局 `_OWNERS` 大小只受本用例影响；
  实际有界淘汰会移除**其他用例**留下的记录，断言依赖用例顺序。
  初次修复传普通 `{}` 还暴露了缺 `move_to_end` 的 `AttributeError`。
- **修复**：monkeypatch 换成全新 `OrderedDict()`/`{}` 隔离。
- **验收**：定向复测该文件 exit=0；轮 2 失败、修复后通过。

### 4. 已知遗留（未修，观察项）

- `test_b01_no_upload_consent...`：三轮中两次失败、单独复跑通过。机制已定位：
  前序用例的后台 job 未收敛，晚到的抽帧被记进当前用例的 tracker
  （断言里出现**别的用例**的 `src.mp4` 路径）。修它需动 fixture 的收敛等待，
  可能影响真实取消语义断言，待单独批次处理。
- `test_vision_cleanup_status.py::test_successful_model_with_failed_cleanup...[motion]`：
  轮 3 失败、单独复跑通过，机制未定。
- 本机 pytest 结束时的垃圾目录批量删除被安全钩子拦截，导致轮 3 的
  summary/junitxml 未能落盘；统计由进度符号（`.F E s x`）逐位反推并与
  `--collect-only` 的 1349 个用例序号比对得出。
